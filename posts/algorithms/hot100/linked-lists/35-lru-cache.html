35 · LRU 缓存 ​

Python 题解以 Python 3.10+ 的力扣环境为背景；节点类型由题目提供。局部代码片段用于说明步骤。

迁移校订

  • 排版说明：示例中的二维参数数组 [[2], ...] 是测试输入，不是 Obsidian 双链。
  • 约束校订：恢复原笔记复制时丢失的指数，如 10^4、10^5、2^31；未修改示例数据。
题目: ​

请你设计并实现一个满足  LRU (最近最少使用) 缓存 约束的数据结构。

实现 LRUCache 类：

  • LRUCache(int capacity) 以 正整数 作为容量 capacity 初始化 LRU 缓存
  • int get(int key) 如果关键字 key 存在于缓存中，则返回关键字的值，否则返回 -1 。
  • void put(int key, int value) 如果关键字 key 已经存在，则变更其数据值 value ；如果不存在，则向缓存中插入该组 key-value 。如果插入操作导致关键字数量超过 capacity ，则应该 逐出 最久未使用的关键字。

函数 get 和 put 必须以 O(1) 的平均时间复杂度运行。

示例：

输入 ["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"] [[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]] 输出 [null, null, null, 1, null, -1, null, -1, 3, 4]

解释 LRUCache lRUCache = new LRUCache(2); lRUCache.put(1, 1); // 缓存是 {1=1} lRUCache.put(2, 2); // 缓存是 {1=1, 2=2} lRUCache.get(1); // 返回 1 lRUCache.put(3, 3); // 该操作会使得关键字 2 作废，缓存是 {1=1, 3=3} lRUCache.get(2); // 返回 -1 (未找到) lRUCache.put(4, 4); // 该操作会使得关键字 1 作废，缓存是 {4=4, 3=3} lRUCache.get(1); // 返回 -1 (未找到) lRUCache.get(3); // 返回 3 lRUCache.get(4); // 返回 4

提示：

  • 1 <= capacity <= 3000
  • 0 <= key <= 10000
  • 0 <= value <= 10^5
  • 最多调用 2 * 105 次 get 和 put

哈希表 + 双向链表（LRU 缓存） ​

解题思路 ​

使用哈希表 + 双向链表实现 LRU 缓存，使 get 和 put 操作的平均时间复杂度都达到 O(1)。

LRU（Least Recently Used，最近最少使用）是一种缓存淘汰策略：

  • 最近访问过的数据，优先保留。
  • 长时间没有访问的数据，优先淘汰。
  • 每次 get 或更新已有的 put，都算一次访问。

需要解决两个问题：

  1. 如何通过 key 快速找到缓存节点？
  2. 如何快速将节点移动到最近使用的位置，并淘汰最久未使用的节点？

因此，我们使用：

  • 哈希表 key_to_node：通过 key 快速找到对应节点。
  • 双向链表：维护节点的访问顺序，支持 O(1) 删除和插入。

关键思想 ​

1. 哈希表：快速查找 ​

python
self.key_to_node = {}

哈希表保存 key 到链表节点的映射：

text
key_to_node = {
    1: 节点(1, 100),
    2: 节点(2, 200)
}

这样，查找 key 时不需要遍历链表，平均时间复杂度为 O(1)。

注意：哈希表保存的是节点引用，而不是单纯保存 key-value 数值。

2. 双向链表：维护访问顺序 ​

使用双向链表维护节点的新旧顺序：

text
dummy ⇄ 最近使用的节点 ⇄ ... ⇄ 最久未使用的节点 ⇄ dummy

本题采用循环双向链表，并使用虚拟头节点 dummy。

  • dummy.next：最近使用的节点。
  • dummy.prev：最久未使用的节点。

每次访问节点，都将它移动到链表头部。

当缓存超过容量时，直接删除链表尾部节点。

为什么使用双向链表？

因为删除一个已知节点时，需要同时修改它的前驱和后继指针：

python
x.prev.next = x.next
x.next.prev = x.prev

不需要遍历链表，因此删除操作的时间复杂度为 O(1)。

3. 为什么使用循环链表和虚拟头节点？ ​

初始化：

python
self.dummy = Node()
self.dummy.prev = self.dummy
self.dummy.next = self.dummy

此时链表为空，dummy 的前驱和后继都指向自己。

使用循环双向链表后，无论链表为空、只有一个节点还是有多个节点，都可以统一处理插入和删除操作，避免反复判断头尾节点。

4. get_node：访问节点并更新顺序 ​

python
def get_node(self, key: int) -> Optional[Node]:
    if key not in self.key_to_node:
        return None

    node = self.key_to_node[key]
    self.remove(node)
    self.push_front(node)

    return node

分为三个步骤：

  1. 如果 key 不存在，返回 None。
  2. 如果存在，从链表当前位置删除该节点。
  3. 将该节点重新插入链表头部，表示它刚刚被访问。

这个函数统一处理了查找和更新访问顺序。

因此，get 和更新已有 key 的 put 都可以复用它。

5. get：获取缓存值 ​

python
def get(self, key: int) -> int:
    node = self.get_node(key)
    return node.value if node else -1

如果节点存在，返回其 value；否则返回 -1。

由于 get_node 已经将节点移动到链表头部，因此不需要重复处理访问顺序。

6. put：插入或更新缓存 ​

python
def put(self, key: int, value: int) -> None:
    node = self.get_node(key)

    if node:
        node.value = value
        return

    self.key_to_node[key] = node = Node(key, value)
    self.push_front(node)

    if len(self.key_to_node) > self.capacity:
        back_node = self.dummy.prev
        del self.key_to_node[back_node.key]
        self.remove(back_node)

分为两种情况。

情况一：key 已经存在

调用 get_node 后，节点已经移动到链表头部，只需更新 value 并返回。

情况二：key 不存在

  1. 创建新节点。
  2. 加入哈希表。
  3. 插入链表头部。
  4. 如果节点数量超过容量，删除链表尾部节点。

淘汰时需要同时更新哈希表和链表：

python
back_node = self.dummy.prev
del self.key_to_node[back_node.key]
self.remove(back_node)

如果只从链表删除而不从哈希表删除，哈希表仍然会保存已经淘汰的节点，导致数据结构不一致。

7. remove：删除指定节点 ​

python
def remove(self, x: Node) -> None:
    x.prev.next = x.next
    x.next.prev = x.prev

让节点的前驱直接连接后继，让后继直接连接前驱。

8. push_front：插入到链表头部 ​

python
def push_front(self, x: Node) -> None:
    x.prev = self.dummy
    x.next = self.dummy.next
    x.prev.next = x
    x.next.prev = x

将节点插入 dummy 和原先第一个节点之间。

插入后，该节点成为最近使用的节点。

执行过程示例 ​

假设缓存容量为 2：

text
put(1, 1)
put(2, 2)
get(1)
put(3, 3)

第一步：put(1, 1) ​

text
最近使用 → [1=1]
最久未使用 → [1=1]

第二步：put(2, 2) ​

text
最近使用 → [2=2] ⇄ [1=1]
最久未使用 → [1=1]

第三步：get(1) ​

访问 key 为 1 的节点，将它移动到链表头部。

text
最近使用 → [1=1] ⇄ [2=2]
最久未使用 → [2=2]

第四步：put(3, 3) ​

插入节点 3 后，缓存超过容量 2。

此时节点 2 最久未被访问，因此淘汰节点 2。

text
最近使用 → [3=3] ⇄ [1=1]
最久未使用 → [1=1]

最终缓存中保留 key 为 1 和 3 的数据。

复杂度分析 ​

  • 时间复杂度： O(1) 平均。

    哈希表查找、链表删除、链表头部插入均为 O(1)，因此 get 和 put 都是平均 O(1)。

  • 空间复杂度： O(capacity)。

    哈希表和双向链表最多保存 capacity 个有效缓存节点，另外还有一个虚拟头节点。

Python 代码 ​

python
from typing import Optional


class Node:
    __slots__ = "prev", "next", "key", "value"

    def __init__(self, key=0, value=0):
        self.key = key
        self.value = value


class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity

        # 循环双向链表的虚拟头节点
        self.dummy = Node()
        self.dummy.prev = self.dummy
        self.dummy.next = self.dummy

        # key -> Node
        self.key_to_node = {}

    # 查找节点，并移动到链表头部
    def get_node(self, key: int) -> Optional[Node]:
        if key not in self.key_to_node:
            return None

        node = self.key_to_node[key]
        self.remove(node)
        self.push_front(node)

        return node

    # 获取缓存
    def get(self, key: int) -> int:
        node = self.get_node(key)
        return node.value if node else -1

    # 插入或更新缓存
    def put(self, key: int, value: int) -> None:
        node = self.get_node(key)

        # key 已存在：更新 value
        if node:
            node.value = value
            return

        # key 不存在：创建新节点
        self.key_to_node[key] = node = Node(key, value)
        self.push_front(node)

        # 超出容量，淘汰最久未使用的节点
        if len(self.key_to_node) > self.capacity:
            back_node = self.dummy.prev
            del self.key_to_node[back_node.key]
            self.remove(back_node)

    # 从链表中删除节点
    def remove(self, x: Node) -> None:
        x.prev.next = x.next
        x.next.prev = x.prev

    # 将节点插入链表头部
    def push_front(self, x: Node) -> None:
        x.prev = self.dummy
        x.next = self.dummy.next
        x.prev.next = x
        x.next.prev = x

易错点 ​

  1. 访问节点必须更新顺序。

    get 成功后，节点必须移动到链表头部，否则无法正确判断最久未使用的节点。

  2. 更新已有 key 也属于一次访问。

    put 更新已有节点时，同样需要将其移动到链表头部。

  3. 淘汰节点时必须同步修改两个数据结构。

    哈希表和双向链表都要删除对应节点。

  4. 注意链表头尾方向。

    本实现规定 dummy.next 是最近使用的节点，dummy.prev 是最久未使用的节点。

  5. 先插入，再判断是否超出容量。

    新节点插入后，如果缓存大小超过容量，就删除链表尾部节点。

总结 ​

LRU 缓存的经典实现：

哈希表负责快速查找，双向链表负责维护访问顺序。

  • get_node：查找并更新访问顺序。
  • get：获取 value。
  • put：插入或更新，必要时淘汰旧节点。
  • remove：删除指定节点。
  • push_front：将节点移动到最近使用的位置。

核心是将哈希表与双向链表结合，使查找、更新、插入和淘汰都能在平均 O(1) 时间内完成。
