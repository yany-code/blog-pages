09 · MCP 模型上下文协议 ​

以下保留原学习资料的章节结构与版本语境；示例依赖对应环境，接入真实项目时需按所用版本配置。

迁移校订

  • MCP 统一的是协议，不统一所有宿主的配置文件或权限管理；mcp.json 在这里仅是宿主配置示意。FastMCP 指示例导入的 MCP Python SDK 接口，不是 Python 标准库。
  • 第 6.3 节是保留的适配器接入草稿，不能直接视为已验证可运行：from_config、客户端生命周期与 get_tools 的异步用法需按安装版本改写。bind_tools 只让模型提出调用请求，还需要应用执行工具并回传结果，才构成完整闭环。

1、为什么需要 MCP？ ​

  1. 过去没有 MCP 时的痛苦（N * M 重复造轮子）
    • 开发者写了一个"查MySQL数据库"的工具;
    • 想在 Cursor 里用, 得按 Cursor 规则写一套;
    • 想在 Claude Desktop 里用, 得按 Anthropic 规则重写一套;
    • 想在 自己的 LangChain 项目里用, 又得写成 Python @tool。
    • 痛点: 工具与宿主应用强绑定, 无法像积木一样跨软件、跨平台复用。
  2. MCP 的终极比喻: AI 世界的"Type-C 统一插口"
    • MCP（Model Context Protocol） 是由 Anthropic 发起并开源的标准化协议。
    • 它的本质: 就像硬件世界的 USB-C / Type-C 接口 —— 鼠标、键盘、U 盘只要符合 Type-C 标准, 无论插在 Mac、Windows、手机还是电视上都能秒识别！
    • 带来的变革: 开发者只需要把外部系统（数据库、本地文件、GitHub、天气 API）写成一个 MCP Server, 所有支持 MCP 的 AI 应用（Cursor、Claude、VS Code、自研 Agent）可以复用同一服务端能力，但仍需核对协议版本、传输、能力和宿主配置。

2、Tool vs RAG vs MCP vs Agent（必背） ​

概念核心职责它在解决什么问题？通俗理解
Tool可调用的函数功能模型能不能执行具体动作螺丝刀本身
RAG知识库检索增强模型能不能查到私有参考资料翻阅本地说明书
MCP跨平台统一通信协议外部工具和资源怎么以统一标准暴露与接入Type-C 通用接口规范
Agent思考与规划大脑谁来根据当前目标决定何时调哪个能力拿着工具箱的工程师

💡 一句话总结：Tool 提供手脚，RAG 提供外挂资料，MCP 统一插口规范，Agent 负责指挥大脑！

3、MCP 的 Host-Client-Server 三层架构 ​

MCP 采用了清晰的三层写作架构（底层基于 JSON-RPC 2.0 通信）:

  1. MCP Host（宿主）: 用户直接打交道的软件（如 Cursor、Claude Desktop、自研 Agent 应用）;
  2. MCP Client（客户端）: Host 内部负责跟某个 MCP Server 通信的协议转接头;
  3. MCP Server（服务端）: 独立运行的服务（本地子进程或远程微服务）, 真正访问文件、数据库或 API。

4、MCP 服务器能对外暴露什么？（三大核心能力） ​

一个标准的 MCP Server 可以对外提供 3 种维度的能力，控制权各不相同:

能力类型中文名谁来触发控制？典型场景
Tools工具模型提出调用请求，应用执行并授权 (Model-controlled)查实时天气、跑 SQL 查库、发请求、算公式
Resources资源宿主程序决定注入 (App-driven)只读文件内容、系统日志、数据库表结构 Schema
Prompts提示词模板人类用户显式选用 (User-controlled)预置的高质量工作流模板（如“代码审查模板”）

5、两大通信传输方式（Transport） ​

传输类型通信方式使用场景特点
stdio

6、实战极简代码范式 ​

6.1、服务端: 用 FastMCP 5 分钟写一个天气 MCP 服务 ​

MCP Python SDK 提供了高层接口 FastMCP, 像写 FastAPI 一样简单:

python
# mcp_weather_server.py
from mcp.server.fastmcp import FastMCP

# 1. 创建 MCP 服务实例
mcp = FastMCP("WeatherSerice")

# 2. 暴露一个 Tool （大模型可自动调用）
@mcp.tool()
def query_weather(city: str) -> str:
	"""查询指定城市的当前天气情况"""
	return f"{city} 当前天气晴朗, 气温 24 ℃"

# 3. 暴露一个 Resource（静态只读上下文）
@mcp.resource("system://info")
def get_system_status() -> str:
	return "Weather Service V1.0 - 运行正常"

# 4. 启动服务（支持 stdio 或 streamable-http）
if __name__ == "__main__":
	mcp.run(transport="stdio")

6.2、客户端配置: mcp.json（统一链接凭证） ​

这是宿主应用（如 Claude / LangChain）用来声明"连哪几台 MCP Server"的配置文件:

json
{
	"mcpServers": {
		"weather": {
			"command": "python",
			"args": ["mcp_weather_server.py"]
		}
	}
}

6.3、LangChain 接入: 把 MCP 工具交给 Agent ​

在 Python 代码中, 通过 LangChain 适配器一键读入并交给 Agent:

python
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.chat_models import init_chat_model

async def run_agent():
	# 1. 读入 mcp.jdon, 建立协议连接
	async with MultiServerMCPClient.from_config("mcp.json") as client:
		# 2. 协议自动握手, 拉去远程工具列表（自动转换成 LangChain Tool）
		tools = client.get_tools()

		# 3. 绑定给模型, 直接成为具备 MCP 能力的智能体！
		model = init_chat_model("deepseek-v4-flash", model_provider="openai")
		agent_model = model.bind_tools(tools)

		# 模型识别到需要查天气, 自动发起 MCP 工具调用！
		res = await agent_model.ainvoke("北京今天天气好不好？")
		print(res.tool_calls)

💡 核心考点与背诵口诀 ​

  1. MCP 是标准接口：如同 Type-C 连外设，一次写好服务，Cursor / Claude / Agent 到处插。
  2. 架构三层要分清：Host 是应用，Client 挂其中，Server 在外跑。
  3. 暴露能力分三种：模型自调走 Tool，只读资料查 Resource，模板人选看 Prompt。
  4. 传输方式两主流：本地子进程走 stdio，远程微服务走 Streamable HTTP。
  5. 协议只管连通路，规划决策归 Agent。
