10 · Agent 智能体 ​

以下保留原学习资料的章节结构与版本语境；示例依赖对应环境，接入真实项目时需按所用版本配置。

1、什么是Agent？（必背公式） ​

大模型不是智能体, 工具也不是智能体。Agent 的最小本质可以概括为一个公式:

Agent=模型(Model)+工具集(Tools)+运行循环(Loop)+当前状态(State)

  • 模型（大脑）: 负责理解目标、分析当前处境、判断下一步该干嘛;
  • 工具集（手脚）: 分组真正执行动作（查天气、查库存、掉数据库、发邮件）;
  • 运行循环（心脏）: 让系统能够 "想一步 -> 做一步 -> 看一眼结果 -> 再决定下一步" , 直到达成目标;
  • 当前状态（便签本）: 记录本轮对话、中间工具调用的过程和结果。

2、核心工作范式：ReAct 范式（Reason + Act） ​

Agent 之所以能解决复杂任务, 核心依赖 ReAct 循环（先推理, 再行动, 再观察）:

现代工程真相：在底层的消息流里，你看到的其实是： AIMessage(tool_calss=[...] ——> ToolMessage(content=...) ——> AIMessage（最终回答）。

3、架构选型：Workflow（工作流） vs Agent（智能体） ​

很多初学者容易盲目堆 Agent。在企业架构评审中，这道选择题必考：

对比维度工作流 (Workflow / LCEL 链)智能体 (Agent)
执行路径固定可预测（A →\to→ B →\to→ C 提前写死）动态不确定（由模型边走边看、临场决定）
调用次数调用几次、按什么顺序，代码里说了算调几次工具、先调哪个，由大模型说了算
成本与耗时确定、高效、成本极低耗时较长、消耗 Token 较多，存在死循环风险
适用场景文本切分入库、固定报表生成、既定业务审批开放式调研、复杂故障诊断、多步骤综合任务

🏆 企业级落地的黄金准则：能用工作流写死的，绝不要用 Agent！ 一种常见设计是：工作流负责主干骨架，Agent 负责不确定节点的动态决策。 是否适合仍需按任务和控制需求权衡。

4、LangChain 版本演进：V0.3（Classic）vs V1.x（Modern） ​

LangChain 的 Agetn 语法经历了一次重构，两套写法都要能看懂：

维度V0.3 / Classic（老版本写法）V1.x / Modern（当前官方主线）
核心 APIcreate_tool_calling_agent + AgentExecutorcreate_agent
组织风格显式拼装：大脑（Agent）和循环驱动器（Executor）分开写一步收口：模型、工具、人设统统打包进统一入口
底层引擎传统的 Python while 循环基于 LangGraph 的图状态机引擎
中间草稿Prompt 里必须显式留一个 {agent_scratchpad}底层自动管理消息状态，无需手动留草稿坑
学习定位适合观察内部运转机制适合新项目开发、生产落地

5、经典代码范式（直接复用） ​

5.1、范式1：现代V1.x 极简 Agent（带结构化输出） ​

python
from pydantic import BaseModel, Field
from langchain.agents import create_agent
from langchain_core.tools import tool

# 1. 准备工具
@tool
def get_weather(city: str) -> str:
    """查询指定城市的天气温度"""
    temps = {"Beijing": "22℃", "Shanghai": "28℃"}
    return temps.get(city, "未知")

# 2. 规定 Agent 最终必须按此结构返回结果
class ComparisonResult(BaseModel):
    hotter_city: str = Field(description="温度更高的城市")
    difference: str = Field(description="两地的温度对比总结")

# 3. 一步创建 Agent（内部自动跑 LangGraph 循环）
agent = create_agent(
    model=model,
    tools=[get_weather],
    system_prompt="你是一个数据分析助手，善于使用工具对比城市气温。",
    response_format=ComparisonResult # 🌟 约束最终输出为强类型对象
)

# 4. 执行多步决策
res = agent.invoke({"input": "今天北京和上海谁更热？"})
print(res["structured_response"])
# 输出: ComparisonResult(hotter_city='Shanghai', difference='上海28℃，比北京22℃高6℃')

5.2、范式2：多智能体协作（A2A / Agent-to-Agent） ​

当任务很复杂时，不要造一个“全知全能的超级 Agent”，而是做领域拆分：

  • 分工原则：各司其职，每个 Agent 的工具集和人设极度精简，避免单一 Agent 挂载几十个工具导致大模型选错工具。

6、知识大串联：五大核心概念终极大汇总（面试必背） ​

学到第21章，整个大模型应用开发的拼图已经全部成型：

概念核心定位一句话通俗解释
Tool能力层工具箱里的扳手、螺丝刀（负责具体干活）
Function Calling调用机制模型递出来的调用申请单（包含函数名与参数）
RAG上下文增强翻阅企业私有知识库（负责补充专业资料）
MCP开放协议标准AI 世界的 Type-C 插口（负责让外部工具随插随用）
Agent决策规划层拿着工具箱、翻着资料、边想边干的工程师（负责统筹全局）

💡 核心考点与背诵口诀 ​

  1. 智能体公式牢记心：模型大脑配工具，循环推演控状态。
  2. ReAct 循环三部曲：一想二干三观察，任务没完接着转。
  3. 固定流程走工作流：步骤写死用 LCEL，动态不确定再上 Agent。
  4. 老版看清执行器：Agent 出主意，Executor 跑断腿，中间草稿记 scratchpad。
  5. 新版一键靠 create_agent：结构化输出加记忆，底层全交 LangGraph。
