11 · LangGraph 概述与快速入门 ​

以下保留原学习资料的章节结构与版本语境；示例依赖对应环境，接入真实项目时需按所用版本配置。

1、为什么需要 LangGraph？ ​

1.1、传统方案的致命局限 ​

  • LCEL / 传统 Chain: 只适合 "一条直线走到底" 的线性单向流（A -> B -> C）。
  • 一旦业务遇到循环改稿、打回重试、根据打分走不同分支，代码里就会充斥着丑陋且脆弱的while True、id-else胶水代码，状态混乱不堪。
  • 纯黑盒 Agent：模型自由度过高，路径完全不可控，容易胡思乱想、死循环，且无法在特定步骤强制暂停等待人工审批。

1.2、LangGraph 的一句话本质 ​

💡**LangGraph = 用“有向图 + 全局状态”来编排和运行复杂 AI 应用的底层运行时（Runtime）。

  • 图（Graph）：把每一步变成“节点（Node）”，把下一步往哪走变成“边（Edge）”，天然支持顺序、条件分支、循环回退、并行汇总。
  • 状态（State）：一张贯穿整个流程的“共享工单/黑板”，所有节点都能读取、更新它。
  • 企业级杀手锏：原生支持**断电续跑（持久化 CheckPointer）与人机协作（Human-in-the-loop，中途暂停等人审批）。

2、LangChain vs LCEL vs Agent vs LangGraph ​

概念表现形态使用场景通俗比喻
LCEL/Chain一条直线固定步骤、单项数据流、无循环工厂的单向流水线
LangGraph一张网复杂长流程、循环修改、多路并行、中断恢复带有十字路口和环岛的告诉公路网
Agent决策应用形态人物路径位置，依赖模型动态规划跑在公路上的自动驾驶汽车

3、LangGraph 四大核心基石（必背） ​

核心概念角色定位它在做什么？代码对应物
state（状态）共享黑板记录当前工作流流转的全部数据class MyState(TypeDict)
Nodes（节点）干活的工人接受当前State，执行逻辑，返回要更新的局部字典普通 Python 函数（调 LLM 或普通代码）
Edges（边）交通指示牌决定当前节点跑完后，下一步去哪个节点add_edge(A, B)、START、END、条件边
Graph（图）调度中枢将 State、Nodes、Edges 组装编译成的可执行图StateGraph(State) -> compile()

4、LangGraph 经典五步构建发（✨标准代码范式） ​

无论多复杂的系统，都严格遵循这 5 个步骤：

极简 HelloWorld 完整骨架：

python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# 第 1 步：定义全局共享状态 (State)
class OverallState(TypedDict):
    name: str
    greeting: str

# 第 2 步：编写节点函数 (Node)
# 本例节点接收 state，并返回局部字典用于更新状态；其它返回形式需按所用 API 定义。
def node_greet(state: OverallState):
    return {"greeting": f"你好，{state['name']}！"}

def node_emoji(state: OverallState):
    return {"greeting": state["greeting"] + " 🎉🎉🎉"}

# 第 3 步：组装图并连线 (Edges)
builder = StateGraph(OverallState)

# 注册节点
builder.add_node("greeting_step", node_greet)
builder.add_node("emoji_step", node_emoji)

# 规划路线：START -> greeting_step -> emoji_step -> END
builder.add_edge(START, "greeting_step")
builder.add_edge("greeting_step", "emoji_step")
builder.add_edge("emoji_step", END)

# 第 4 步：编译图 (Compile)
app = builder.compile()

# 第 5 步：调用执行 (Invoke)
result = app.invoke({"name": "张三"})
print(result)
# 输出: {'name': '张三', 'greeting': '你好，张三！ 🎉🎉🎉'}

5、覆盖更新 vs 追加更新（add_messages） ​

在 LangGraph 中，节点返回局部字典时，默认逻辑是覆盖（Overwrite）：

  • 案例中 x = 5，下一个节点返回 {"x": 10}，最终状态中 x 就变成了 10。

但在多轮对话和 Agent 场景中，聊天消息绝不能被覆盖，必须不断追加！ 这就要引入 Reducer 机制（使用 add_messages）：

python
from typing import Annotated
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages

class ChatState(TypedDict):
    # 🌟 Annotated + add_messages：声明该字段不是覆盖，而是把新消息自动 append 到列表末尾！
    messages: Annotated[list[BaseMessage], add_messages]

def model_node(state: ChatState):
    # 调模型，拿到新回复
    ai_msg = model.invoke(state["messages"])
    # 节点只需返回新增的消息，系统会自动追加！
    return {"messages": [ai_msg]}

6、拓扑可视化：把代码打印成图 ​

LangGraph 最大的优势之一是可视化排障，编译后可直接导出结构图：

python
# 1. 在终端直接输出 ASCII 字符流程图
print(app.get_graph().print_ascii())

# 2. 导出 Mermaid 语法代码（复制到 mermaid.live 网页直接看图）
print(app.get_graph().draw_mermaid())

💡 核心考点与背诵口诀 ​

  1. 直线走 LCEL，网状上 LangGraph：遇到循环、回退、人工审，图编排是唯一解。
  2. 核心四大件：State 记数据，Node 干具体活，Edge 指流向，Graph 统全局。
  3. 节点编写黄金律：入参必是当前 state，返回值必须是更新 dict。
  4. 编译才能跑：写完必须调 compile()，生成 App 才能 invoke。
  5. 对话消息防覆盖：普通字段默认盖，消息追加靠 add_messages。
