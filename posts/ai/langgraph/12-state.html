12 · LangGraph API：图与状态 ​

以下保留原学习资料的章节结构与版本语境；示例依赖对应环境，接入真实项目时需按所用版本配置。

1、State 的终极公式（必背） ​

在 LangGraph 中，状态（State）不是普通 Python 变量，而是整张图的唯一事实来源（Single Source of Truth）。

**State = Schema（字段长什么样） + Reducer（更新时怎么合并）**
  • Schema（数据骨架）：规定图里有哪些字段、格式什么数据类型；
  • Reducer（合并规则）：规定当节点返回局部更新时，新值和旧值到底该“覆盖”、“追加”还是“累加”。

2、三大 Schema 边界（企业级服务必用） ​

如果直接把内部完整 State 暴露给外部API，调用方会看到所有内部临时草稿、思考过程或检索细节。LangGraph 提供了优雅的内外三层隔离：

参数名角色定位核心职责通俗理解
state_schema（即 OverallState）内部工作台包含整张图所有节点需要读写的所有字段厨房里所有的半成品、调料、厨具
input_schema外部进门契约限制外部invoke()只能串哪些字段进图顾客的点餐单（只允许填菜名，不能直接操作厨房）
output_schema外部交付契约限制图执行完毕后，最终只把哪些字段返回给外部最终端上桌的成菜（不把后厨垃圾和草稿端出去）
范式代码：
python
class InputState(TypeDict):
	question: str  # 外部只需传问题

class OutputState(TypeDict):
	answer: str    # 外部最终只想拿答案

class OverallState(TypeDict):
	question: str
	retrieved_docs: list[str]  # 内部检索中间件
	internal_thought: str      # 内部思考草稿
	answer: str

# ✨ 声明时明确内外边界：
builder = StateGraph(OverallState, input_schema=InputState, output_schema=OutputState)

3、Reducer（状态合并规约）全家桶（✨核心避坑点） ​

节点函数千万不要自己去拼完整的全局 State，节点只需要返回局部字典更新（如return {"socre": 10}）。 系统会根据字段在Annotated里绑定的 Reducer 函数，决定怎么合入旧状态 5 大 Reducer 策略速查与选型表：

规约策略声明语法运行机制使用业务字段
1.默认覆盖（Default）field: str新值直接替换旧值latest_answer、current_step、状态标记
2.消息追加（✨核心）Annotated[list, add_messages新消息追加到末尾；若id相同则原地更新；自动反序列化为 Message 对象对话历史messages、Agent轨迹
3.列表拼接Annotated[list[str], operator.add]old_list + new_list拼接标签列表tags、检索候选片段docs
4.数值累加Annotated[int, operator.add]old_val + new_val算术加错误重试次数retry_count、Token 成本消耗
5.自定义函数Annotated[Y, my_reducer]自己写def my_reducer(current, update)列表去重、保留最高置信度、复杂字典合并

4、经典代码范式（直接复用） ​

包含多种合并策略的符合聊天机器人 State

python
import operator
from typing import Annotated, TypedDict
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages
from langgraph.graph import StateGraph, START, END

# 1. 精心设计不同字段的合并行为
class BotState(TypedDict):
    # 消息必须追加，绝不能覆盖！
    messages: Annotated[list[BaseMessage], add_messages]
    # 标签列表：多节点各自产生标签，自动拼接合并
    tags: Annotated[list[str], operator.add]
    # 累计分数：多节点打分求和
    total_score: Annotated[int, operator.add]
    # 最新生成的摘要：后节点直接覆盖前节点
    latest_summary: str

# 2. 编写节点：只返回局部更新
def extract_node(state: BotState):
    return {
        "tags": ["AI", "Python"],
        "total_score": 10
    }

def chat_node(state: BotState):
    return {
        "tags": ["LangGraph"],
        "total_score": 20,
        "latest_summary": "已完成首轮交互"
    }

# 3. 组装与执行
builder = StateGraph(BotState)
builder.add_node("extract", extract_node)
builder.add_node("chat", chat_node)

builder.add_edge(START, "extract")
builder.add_edge("extract", "chat")
builder.add_edge("chat", END)

app = builder.compile()

# 执行后观察合并结果：
# tags 自动合并为: ['AI', 'Python', 'LangGraph']
# total_score 自动累加为: 30
# latest_summary 覆盖为: '已完成首轮交互'

5、图在运行时如何推进？（Pregel 架构） ​

为什么 LangGraph 能够支持复杂的并行与循环？它的底层是基于 Pregel 批量图计算模型 运算的：

  • 并行节点的安全性：如果节点 A 和 节点 B 在同一个 Superstep 里同时运行，并且都修改了tags字段，他们不会打架！因为运行时会在 Step3 中，统一调用tags的 Reducer 将两者安全合并。 状态快照（StateSnapshot 与时间旅行）： 通过配置 Checkpointer，运行时会在每一个 Superstep 结束时保存一份快照。
  • app.get_state(config): 查看当前会话在这一步的完整状态快照
  • snapshot.next: 告诉你继续往下走，下一步将执行哪几个节点（实现人工介入、中断审批、回溯重跑的底层根基！）。

💡 核心考点与背诵口诀 ​

  1. State 是核心单一本：所有的节点围它转，进门出户 Schema 设防线。
  2. 节点只返局部量：莫把全量 State 传，局部字典最规范。
  3. 字段更新看 Reducer：没写就是覆盖换，聊天必须加 add_messages。
  4. 列表累加用 operator.add：数值计费也靠它，特殊逻辑自己写。
  5. 底层调度叫 Superstep：计划、执行、再更新，并行合并靠规约。
