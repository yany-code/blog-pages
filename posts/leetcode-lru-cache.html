手写 LRU 缓存：哈希表与双向链表如何配合 ​

LRU 这道题的难点不是记住一个淘汰规则，而是让“找到数据”和“调整访问顺序”都足够快。把这两个职责交给不同的数据结构，再保证它们始终同步，就能得到清楚的实现。

题意与数据结构选择 ​

LeetCode 146：LRU 缓存 要求实现固定正容量的缓存：get 返回已有值或 -1；put 插入或更新数据，容量不足时淘汰最久未使用的键。两种操作都要求平均 O(1)。

哈希表可以按键定位，却不擅长删除访问顺序中间的元素。双向链表只要拿到节点引用，就能在常数时间内摘下节点、插入头部。因此表里应保存 key -> Node，链表负责维护新旧顺序。

用一个哨兵统一头尾操作 ​

沿用练习笔记中的循环双向链表，让虚拟节点 dummy 同时连接头尾：

text
dummy ⇄ 最近使用 ⇄ …… ⇄ 最久未使用 ⇄ dummy

空缓存中，dummy.next 和 dummy.prev 都指向自身。所有真实节点都具备前驱与后继，所以删除和插入不必分别处理首节点、尾节点。

约定 dummy.next 最近、dummy.prev 最旧。访问命中的节点，或更新已有键，都需要先摘下，再插入头部。新键直接插入头部，超过容量后淘汰尾部。

始终保持的两个不变量 ​

第一，哈希表中的每个节点都在链表中出现一次，链表中的每个真实节点也都能通过键找到。删除缓存项必须同时修改两边，不能只摘链表而遗留哈希映射。

第二，链表从头到尾按最近访问时间排列。get 命中和 put 更新都算访问；get 未命中则没有节点需要移动。把移动封装为 moveToFront，可以避免两处操作各写一份指针修改逻辑。

走一遍淘汰与更新 ​

设容量为 2，下面的顺序均从最近使用写到最久未使用：

操作链表中的键结果
put(1, 10)1插入
put(2, 20)2 → 1插入
get(1)1 → 2返回 10，1 移到头部
put(3, 30)3 → 1淘汰 2
put(1, 11)1 → 3更新已有值，容量不变

最后一步尤其容易遗漏：更新已有键虽然没有增加元素个数，却改变了访问顺序。

Java 实现 ​

java
import java.util.HashMap;
import java.util.Map;

class LRUCache {
    private static class Node {
        int key;
        int value;
        Node prev;
        Node next;

        Node(int key, int value) {
            this.key = key;
            this.value = value;
        }
    }

    private final int capacity;
    private final Map<Integer, Node> nodes = new HashMap<>();
    private final Node dummy = new Node(0, 0);

    public LRUCache(int capacity) {
        this.capacity = capacity;
        dummy.next = dummy;
        dummy.prev = dummy;
    }

    public int get(int key) {
        Node node = nodes.get(key);
        if (node == null) {
            return -1;
        }
        moveToFront(node);
        return node.value;
    }

    public void put(int key, int value) {
        Node node = nodes.get(key);
        if (node != null) {
            node.value = value;
            moveToFront(node);
            return;
        }

        node = new Node(key, value);
        nodes.put(key, node);
        pushFront(node);

        if (nodes.size() > capacity) {
            Node oldest = dummy.prev;
            remove(oldest);
            nodes.remove(oldest.key);
        }
    }

    private void moveToFront(Node node) {
        remove(node);
        pushFront(node);
    }

    private void remove(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void pushFront(Node node) {
        node.prev = dummy;
        node.next = dummy.next;
        dummy.next.prev = node;
        dummy.next = node;
    }
}

复杂度与易错点 ​

一次操作只有常数次哈希查找、插入、删除和指针修改，因此 get、put 的平均时间都是 O(1)。哈希表和链表保存至多 capacity 个有效节点，空间为 O(capacity)。

  • 哈希表存节点引用，才能直接修改该节点的位置。
  • 淘汰尾节点时，要保留它的 key 用于删除映射。
  • 已有键的更新必须直接返回，避免再次创建同键节点。
  • 容量为 1、重复更新同一键、读取不存在的键，是最基本的检查场景。
  • 这份实现遵循题目约束，未添加并发访问控制；作为应用缓存使用时，需要另行设计同步策略。

手写这一遍以后，最该记住的是两个结构的分工与一致性：哈希表解决定位，双向链表解决顺序，每次操作同时维护两者。
