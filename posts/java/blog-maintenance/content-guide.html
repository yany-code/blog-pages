二、个人基础信息（site.ts） ​

文件：blog\docs\.vitepress\theme\site.ts

这是全站常量的唯一来源，登录屏、开始菜单、窗口标题里的昵称都从这里读：

ts
export const SITE = {
  name: 'Yany_uki',                                 // 昵称
  signature: '这不是英雄的故事，但终将造就英雄',       // 个性签名
  motto: '以代码为剑，奔赴热爱',                      // 欢迎屏标语
  avatar: 'https://cdn.jsdelivr.net/.../yuki.jpg',   // 头像
  wallpaper: '.../%E5%A3%81%E7%BA%B8.jpg',           // 桌面壁纸
  github: 'https://github.com/yany-code',            // 社交链接
  bilibili: 'https://b23.tv/yci3XAr',
  qq: '1264660998'
}
  • 只改引号里的内容，注意保留引号和逗号
  • 换头像 / 壁纸：PicGo 上传新图后，把对应字段的链接替换掉即可
  • ⚠️ QQ 号在 about.md 正文里还出现了一次，换号的话两处一起改

三、自我介绍（about.md） ​

文件：blog\docs\about.md。打开后从上到下就是「我的电脑」窗口的展示顺序，直接改文字：

区块怎么改
顶部头像 <img ...>只改 src 为新图链接（已内置 CDN 失败兜底，不用动其他属性）
# 关于我 下面的引用块自我介绍正文，"你好呀，我是 Yany_uki……"，随便写
## ✨ 个性签名引用块里的一句话

文件最上方 --- 之间的 title / description 是浏览器标签标题和 SEO 摘要，可顺手改。

五、博客文章：编写与推新（posts/） ​

1. 写新文章 ​

在 blog\docs\posts\ 下新建一个 .md 文件（文件名建议英文或拼音，它就是文章链接），套模板：

md
---
title: 文章标题
date: 2026-09-07
description: 一句话简介（会显示在文章列表卡片上）
---

# 文章标题

正文用普通 Markdown 写：标题、列表、表格、代码块、图片都支持。

要点：

  • --- 之间是 frontmatter，必须保留，三行都建议写
  • date 决定文章列表的排序（新的在前），推新时写当天日期
  • description 会显示在「技术笔记」窗口的文章卡片上
  • 标题层级从 # 开始，正文里的 ##、### 会自动生成干净的锚点链接

2. 推新（发布新文章） ​

列表页不用动：posts\index.md 里的 <PostList /> 会自动读取 posts\ 目录下所有文章并按日期排序。写完 md → 发布，列表自动多一张卡片。

3. 删文章 ​

直接删除对应 .md 文件，列表自动少一条（注意别删 posts\index.md，那是列表页本身）。

六、音乐播放器：加歌（music-list.js） ​

「我的音乐」窗口的歌单来自 blog\docs\.vitepress\theme\music-list.js，加歌两步：先传音频文件，再登记一行。

1. 上传音乐文件（二选一） ​

方式 A：图床 jsDelivr（推荐，不占博客仓库）

  1. 打开 github.com/yany-code/blog-images → Add file → Create new file → 输入 music/.gitkeep → Commit（创建 music/ 目录，只需做一次）
  2. 进入 music/ 目录 → Add file → Upload files → 上传 mp3 → Commit
  3. 链接格式：https://cdn.jsdelivr.net/gh/yany-code/blog-images@main/music/文件名.mp3（浏览器打开能播即成功）

方式 B：放进博客本体

把 mp3 放到 blog\docs\public\music\ 目录，链接直接写 /music/文件名.mp3（与站点同源、国内可达性最稳，但会占仓库体积；现在的占位示例曲 demo-song.mp3 就在这里，加了正式歌曲后可删掉它）。

2. 登记到歌单 ​

打开 music-list.js，照格式加一行：

js
export const PLAYLIST = [
  // …已有歌曲…
  {
    title: '歌名',
    artist: '歌手',
    url: 'https://cdn.jsdelivr.net/gh/yany-code/blog-images@main/music/your-song.mp3'
  }
]

保存后「我的音乐」列表里就会出现这首歌，删歌同理删行。

3. 音乐文件要求 ​

项目要求
格式mp3（flac/wav 先用格式工厂等工具转码）
码率128–192kbps（4 分钟的歌约 4–6MB）
大小方式 A 单文件 ≤ 20MB（jsDelivr 硬限制）；方式 B 无此限制
文件名英文或拼音（中文文件名链接要做 URL 编码）
版权只放版权干净的音频：自制、CC 授权、免版权曲库（如 Pixabay Music）

播放功能无需任何配置：循环模式（列表/单曲/随机）、进度拖拽、音量记忆（自动保存）、失败自动跳下一首都是现成的。列表里灰色划线的歌 = 加载失败，点一下它会自动重试。

七、欢迎窗口与 404 页 ​

  • blog\docs\index.md：登录后自动弹出的「欢迎」窗口内容（问候语、图标使用说明、小贴士），改文字即可
  • blog\docs\404.md：404 页文案，一般不动
  • 这两个页面的 h1 上如果有 {#xxx} 手写锚点，留着或删掉都可以——没有锚点时系统会自动生成干净链接

八、站点标题与 SEO（config.mjs） ​

文件：blog\docs\.vitepress\config.mjs，一般设一次就不用动：

配置项作用
title / titleTemplate浏览器标签页标题
description全站默认 SEO 摘要
head 里的 og:* / twitter:*分享到社交平台的卡片标题、描述、配图
buildEnd（sitemapPlugin）自动生成 sitemap.xml，不用手动维护

九、图片上传（PicGo 图床） ​

  1. 用 PicGo 把图片上传到图床仓库 yany-code/blog-images 的 images/ 目录
  2. 拿到 jsDelivr 链接，格式固定为：
md
![图片描述](https://cdn.jsdelivr.net/gh/yany-code/blog-images@main/images/文件名)
  1. 建议文件名用英文（如 frieren.jpg）；中文文件名的链接必须做 URL 编码才能访问（如 壁纸.jpg → %E5%A3%81%E7%BA%B8.jpg）

图床挂了也不怕：头像和壁纸都做了兜底（头像有本地替代图，壁纸有 CSS 重绘的蓝天绿丘）。

十、本地预览与上传同步（发布流程） ​

1. 本地预览（可选，推荐） ​

在 blog\ 目录下执行：

npm run dev

浏览器打开 http://localhost:5173/blog-pages/，改 md 会实时热更新，边改边看。

2. 正式发布（只需一步） ​

双击 blog\deploy.bat（或在 blog\ 目录执行 bash deploy.sh），脚本自动做完四件事：

  1. 把源码仓库 blog/ 提交并推送（git commit + push）
  2. npm run build 打包
  3. 清空发布仓库 blog pages/，复制新构建产物进去，提交推送
  4. 推送完成，等待 1–2 分钟，线上生效

线上地址：https://yany-code.github.io/blog-pages/

3. 发布前检查构建结果（可选） ​

npm run build
npm run preview

预览地址 http://localhost:4173/blog-pages/，确认没问题再 deploy。

十一、注意事项与常见问题 ​

  1. frontmatter 必须保留：md 文件顶部 --- 之间的三行（title/date/description）不要删，格式不要坏
  2. 发布报错先看这两点：改动是否已保存；网络是否可达 GitHub。确认后重跑一次 deploy.bat
  3. 文章列表没更新：检查新文章的 date 是否写对（它决定排序），以及文件是否放在 posts\ 目录下
  4. 改完线上没变化：GitHub Pages 有 1–2 分钟缓存延迟，等一下再刷新
  5. 换 QQ 号：site.ts 和 about.md 两处都要改
  6. 中文文件名图片：引用时必须 URL 编码，建议直接用英文文件名
  7. first-post.md 是示例文章，学会格式后可以删除，列表会自动少一条
  8. 不要动的东西：theme\components\ 下的界面代码、deploy.sh 里的发布逻辑——除非你想改功能而不是内容
  9. 音乐放不出来：先在浏览器直接打开歌曲链接测试能否播放；打不开就检查文件名（中文要 URL 编码）和大小（方式 A 限 20MB，超了换方式 B 或压码率）；播放器里灰色划线的歌点一下即重试
  10. 头像/壁纸偶尔加载失败：多半是 jsDelivr 大陆节点间歇抽风，图床仓库里的文件并没丢；Ctrl+F5 强刷或换个网络即可。界面有兜底不会开天窗（头像显示字母、壁纸显示蓝天绿丘），链接彻底坏了就换一张新图更新 site.ts
  11. 图床 / 音乐文件大小与命名：所有走 jsDelivr 的文件都遵守「英文文件名 + 单文件 ≤ 20MB」，一步到位省去编码和超限的麻烦
