把 Python 数据处理脚本拆清楚：读取、计算与输出各司其职 ​

一个读取 CSV、计算分类金额、生成报告的小脚本，最初可以全部写在一个函数里。但当输入增加 JSON、输出增加 Markdown，或者需要给读取过程加日志时，同一段代码就容易同时承担好几种职责。

整理 Python 学习笔记时，值得保留的是一种拆分方法：先区分数据从哪里来、怎样计算、如何呈现，再决定是否拆成多个文件。下面用一个独立的例子说明，代码只依赖 Python 标准库，适用于 Python 3.12。

先划分职责，再划分文件 ​

数据处理可以沿着一个方向流动：

text
CSV 文件 → 读取与校验 → Sale 对象 → 分类汇总 → JSON 文本 → 写入文件
部分输入与输出负责的事情
读取层路径 → 数据对象打开文件、解析 CSV、检查必需字段
计算层数据对象 → 汇总结果分组、累加；不打开文件、不打印
渲染层汇总结果 → 字符串决定字段、金额格式和 JSON 排版
入口文件路径与各层函数决定调用顺序，以及结果最终写到哪里

这时，换输入格式主要改读取层，换报告格式主要改渲染层。入口可以同时打印和保存同一份文本，不需要让计算函数知道终端或文件的存在。

一个可以独立运行的例子 ​

先把以下内容保存为 sales.csv：

csv
category,quantity,unit_price
键盘,2,99.90
鼠标,1,49.50
键盘,1,10.00

再将下面的代码保存为同一目录下的 report.py：

python
import csv
import json
from collections.abc import Iterable
from dataclasses import dataclass
from decimal import Decimal, InvalidOperation
from pathlib import Path


@dataclass(frozen=True)
class Sale:
    category: str
    quantity: int
    unit_price: Decimal


def read_sales(path: Path) -> list[Sale]:
    records = []
    with path.open(encoding="utf-8-sig", newline="") as file:
        reader = csv.DictReader(file)
        required = {"category", "quantity", "unit_price"}
        if not required.issubset(reader.fieldnames or []):
            raise ValueError("CSV 缺少必需字段")
        for row in reader:
            try:
                category = (row.get("category") or "").strip()
                quantity = int(row.get("quantity") or "")
                price = Decimal(row.get("unit_price") or "")
                if not category or quantity <= 0:
                    raise ValueError("类别不能为空，数量必须为正整数")
                if not price.is_finite() or price < 0:
                    raise ValueError("单价必须是有限的非负数")
            except (ValueError, InvalidOperation) as error:
                raise ValueError(f"CSV 第 {reader.line_num} 行无效") from error
            records.append(Sale(category, quantity, price))
    return records


def summarize(records: Iterable[Sale]) -> dict[str, Decimal]:
    totals: dict[str, Decimal] = {}
    for record in records:
        amount = record.quantity * record.unit_price
        totals[record.category] = totals.get(record.category, Decimal("0")) + amount
    return totals


def render_json(totals: dict[str, Decimal]) -> str:
    data = {key: format(value, ".2f") for key, value in sorted(totals.items())}
    return json.dumps(data, ensure_ascii=False, indent=2)


if __name__ == "__main__":
    text = render_json(summarize(read_sales(Path("sales.csv"))))
    Path("report.json").write_text(text, encoding="utf-8")
    print(text)

在该目录运行 python report.py，终端和生成的 report.json 都会得到：

json
{
  "键盘": "209.80",
  "鼠标": "49.50"
}

CSV 读到的是字符串，因此类型转换放在读取边界完成。这里从十进制字符串构造 Decimal，金额在渲染时才格式化为两位小数的字符串。CSV 文件使用 newline="" 打开，将换行处理交给 csv 模块；utf-8-sig 则兼容带 UTF-8 BOM 的文件。

为什么要有数据对象 ​

如果整个流程都传裸字典，每个函数都需要记住 "category"、"quantity" 等键名。Sale 把这些约定集中到一处，编辑器也更容易提供属性补全。

但类型注解并不等于运行时校验：Sale 的构造函数不会自动保证数量为正，校验仍要在读取层明确实现。frozen=True 限制的是字段重新赋值，字段里若放可变容器，也不会自动变成深度不可变对象。本例只使用字符串、整数和 Decimal，边界比较简单。

把计算与副作用分开，测试才更直接 ​

summarize() 不关心 CSV 文件，所以测试计算不需要先创建文件。把函数定义导入后，可以直接验证：

python
from decimal import Decimal
from report import Sale, render_json, summarize

records = [Sale("键盘", 2, Decimal("99.90"))]
assert summarize(records) == {"键盘": Decimal("199.80")}
assert summarize([]) == {}
assert '"199.80"' in render_json(summarize(records))

同样，render_json() 只返回文本。它没有悄悄写文件，因此既能用于终端预览，也能被网页接口复用。真正的磁盘写入集中在入口，调用者可以看见副作用发生的位置。

示例把记录放进列表，方便观察每一层的结果。处理大文件时，可以把读取层改成生成器；summarize() 已接受 Iterable，不必跟着改变。但生成器中的解析错误会在消费时才出现，因此入口需要同时覆盖读取与汇总阶段的异常，而不能只围住“创建迭代器”的那一次调用。

错误策略也应当有边界 ​

这个示例遇到非法记录会停止，并报告所在行；缺失文件则保留 FileNotFoundError，没有统一包装成含义模糊的“处理失败”。

原笔记还有“跳过脏数据并记录原因”的模式，它适合允许部分成功的导入任务，但不该成为所有项目的默认规则。如果需要支持，应返回合法记录与跳过记录两份结果，让调用者知道报告缺了什么。参数本身不合法时，则应在读取大文件之前尽早报错。

项目变大后，可以按职责拆成 models.py、readers.py、aggregate.py、writers.py 和入口脚本。让数据模型不依赖读写层，读写层不反过来调用入口，依赖方向就更容易保持清楚。小脚本先保留在一个文件里也完全可以，关键是函数之间的职责已经分开。
